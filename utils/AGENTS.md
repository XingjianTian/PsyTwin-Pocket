# utils 目录说明

## 概述
本目录包含 PsyTwin-Pocket 项目的共享工具模块。这些模块为页面、组件和 Behavior 提供基础逻辑支持，确保代码逻辑在全局范围内保持一致。

## 查找位置
- **utils/util.js**: 存放通用的工具函数。包括但不限于时间格式化、对象深拷贝、防抖节流等不涉及业务状态的纯函数。
- **utils/eventBus.js**: 实现全局事件总线。它采用发布订阅模式，主要用于解决小程序中跨页面或深层嵌套组件之间的通信难题。

## 规范
- **按需导入**: 页面、组件或 Behavior 应当根据需要导入特定的工具函数。不要一次性导入整个模块，以保持代码引用清晰。
- **纯函数原则**: `util.js` 中的函数应尽量保持纯净。它们不应直接修改全局变量或产生副作用，输入相同参数应始终返回相同结果。
- **事件总线场景**: `eventBus` 仅用于处理全局状态变化。典型的应用场景包括消息未读数更新、用户登录状态同步或跨页面的数据刷新通知。
- **及时销毁**: 在页面或组件销毁时，务必在 `onUnload` 或 `detached` 生命周期中调用 `eventBus.off` 移除监听器。这能有效防止内存泄漏和逻辑重复触发。
- **导出方式**: `util.js` 采用命名导出（Named Export），方便开发者通过解构赋值引入所需功能。
- **命名约定**: 事件名称应使用小驼峰命名法，并尽量包含动作描述，如 `userLoginSuccess`。

## 代码示例

### 导入工具函数
```javascript
import { formatTime } from '../../utils/util';
```

### 使用事件总线
```javascript
// 监听事件
eventBus.on('updateUnreadCount', (count) => {
  this.setData({ unreadCount: count });
});

// 触发事件
eventBus.emit('updateUnreadCount', 5);
```

## 维护建议
- 新增工具函数前，请先检查 `util.js` 中是否已有类似实现。
- 避免将过于复杂的业务逻辑放入 `utils`。如果逻辑与特定业务强相关，应考虑放在 `api/` 或对应的 `behavior/` 中。
- 保持函数命名语义化，确保其他开发者能通过名称快速理解其用途。
- 定期清理不再使用的工具函数，保持代码库精简。
