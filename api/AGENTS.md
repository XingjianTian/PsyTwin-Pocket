# API 目录指南

## 概述
本目录构成了项目的 HTTP 请求层。它负责定义所有的后端服务接口，确保前端与服务器之间的数据交互保持一致且可控。通过统一的请求封装，我们实现了 Token 管理、错误拦截以及 Mock 数据的无缝切换。

## 查找位置
- **api/request.js**: 核心请求工具。该文件封装了微信原生的 `wx.request` 接口，统一处理请求头配置、Token 自动注入以及 Mock 数据的降级逻辑。
- **API 服务模块**: 位于 `api/` 目录下的业务逻辑文件（如 `user.js`, `home.js` 等）。这些模块直接调用 `request.js` 导出的方法，为页面和组件提供语义化的数据接口。

## 规范

### 请求工具职责
请求封装层必须处理以下核心逻辑，严禁在业务层重复实现：
- 设置默认的 `Content-Type` 为 `application/json`。
- 在请求头中自动携带 `Authorization` Token，处理登录态校验。
- 根据 `config/index.js` 中的全局配置切换 Mock 模式。
- 统一拦截响应状态码，对 401、500 等常见错误进行初步处理或跳转。

### 调用准则
为了维持架构的整洁与可维护性，请遵守以下调用规则：
- 严禁在任何页面（Pages）或组件（Components）中直接调用 `wx.request`。
- 所有的网络请求都必须通过 API 层的服务模块进行转发。
- 页面层只负责调用服务模块并处理返回的 Promise 结果。

### 导入顺序
代码中的 `import` 语句应遵循以下顺序，保持代码整齐：
1. 微信内置模块或全局对象。
2. 外部第三方库（如 TDesign 相关组件或工具）。
3. 项目内部的工具类、行为（Behaviors）或配置文件。
4. 同目录下的其他服务模块。

### 模块化分组
服务模块应当根据功能领域进行逻辑分组，避免单个文件过大：
- 相关的接口函数需要归类到同一个文件中。
- 例如，所有与用户账户、权限相关的接口应放在 `user.js` 中。
- 与首页内容、推荐列表相关的接口则应放在 `home.js` 中。

### 命名约定
导出的请求函数应使用清晰的动词开头，以便于在调用时快速理解接口用途：
- 获取数据：使用 `fetch` 或 `get` 前缀，如 `fetchUserInfo`。
- 提交/更新数据：使用 `update` 或 `post` 前缀，如 `updateSettings`。
- 删除数据：使用 `delete` 或 `remove` 前缀。

### 异步处理
所有 API 函数必须返回 Promise 对象。在页面调用时，推荐使用 `async/await` 语法来处理异步逻辑，确保代码的可读性。
