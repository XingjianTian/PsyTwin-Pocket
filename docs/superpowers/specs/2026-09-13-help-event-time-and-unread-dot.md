# 求助事件通知时间与未读红点

> 设计日期：2026-09-13
> 相关文件：`pages/pet/index.wxml`、`pages/pet/index.js`、`pages/pet/index.less`

## 目标

1. 求助事件卡片（含“温馨通知”）显示醒目的通知时间，让用户知道事件是何时产生的。
2. 底部求助入口的红点不再显示数量，只保留一个红点；每条未点击过的事件在卡片右上角显示红点，点击后消失。

## 实现要点

- 时间来源为事件自身的 `createdAt`（服务端事件与本地演示事件均已携带），缺失时回退 `deadline`；由 `decorateHelpEvents()` 预计算 `timeText`，避免在 WXML 中调用逻辑。
- 展示格式：当天为 `今天 11:43`，前一天为 `昨天 20:15`，更早为 `09-13 11:43`。
- 已读状态以事件 id 集合持久化在本地存储 `petReadHelpEventIds`（上限 200 条），因此服务端状态刷新覆盖事件对象后，红点状态依然正确。
- 底部红点显示条件由 `hasEvent` 改为 `hasUnreadEvent`（存在未读事件），点击事件后即时重算。
- 已解决事件不参与未读判定。

## 行为约束

- 不修改心宠同步服务器的事件契约，未读状态完全由 Pocket 本地维护。
- 已读集合只增不减地记录 id，超出上限后按时间顺序淘汰最早的记录。
- 时间与红点均为纯展示层信息，不影响高危/中危/低危的分流逻辑。
