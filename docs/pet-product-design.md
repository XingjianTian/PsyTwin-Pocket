## 1. 产品概述

### 1.1 定位
**心宠**是 PsyTwin 口袋版的核心特色功能。用户打开小程序心宠页签，即可看到一个在虚拟世界中自主生活的虚拟宠物。心宠有自己的性格、心情、能量和社交属性，会自行决定何时吃饭、睡觉、学习、探索。用户不直接控制心宠，而是在大型事件发生时提供协助。

### 1.2 核心理念
- **虚拟映射**: 心宠给用户"这是我的映射"的感觉，但属性由服务器随机生成
- **自主生活**: 心宠拥有独立AI，用户不直接控制
- **沉浸体验**: 虚拟世界与现实时间同步
- **情感连接**: 心宠遇到问题时向用户求助，建立情感纽带

### 1.3 与PsyTwin生态的关系
```
PsyTwin-Pocket (微信小程序)     PsyTwin-Pet (Node.js服务)      PsyTwin-Sentinel (Next.js)
├─ 心宠页签                      ├─ AI引擎运算                   ├─ 状态提醒管理后台
├─ Canvas 2D渲染                 ├─ WebSocket推送                ├─ 状态提醒列表/处理
├─ 状态栏/按钮面板               ├─ HTTP API                     └─ 学生/教师管理
└─ 事件解决交互                  └─ 数据持久化
```

## 2. 核心原则决策

### 2.1 心理映射：娱乐化随机人格（非真实测评）

**决策**: 心宠的性格与属性由服务器**随机生成**，**不接入**真实心理测评数据。

| 维度 | 处理方式 | 说明 |
|------|---------|------|
| **物种** | 随机（猫/狗/鸟/兔/狐） | 给用户暗示"因为你内向所以是猫" |
| **性格** | 随机 30-70 区间 | 避免极端值，营造"映射感" |
| **名字** | 服务器随机生成 | 如"小安"、"墨墨" |
| **外观** | 随机配色+配饰 | 毛色、配饰随机组合 |

**用户感受 vs 实际数据**:
```
用户感受: "哇，这只猫好像真的代表我"
实际数据: 完全随机，与真实情绪状态无关
```

**禁用术语**: "心理测评映射"、"心理健康状态"、"心理预警"、"心理干预"、"心理诊断"
**替代术语**: "虚拟人格"、"心宠心情"、"心宠状态提醒"、"人工关怀"

### 2.2 MVP范围：单宠物、单场景、无真实社交

| 功能 | MVP (Phase 1) | Phase 2 | Phase 3 |
|------|--------------|---------|---------|
| **宠物数量** | 1只 | 1只 | 1只 |
| **场景数量** | 1个（奇幻森林） | 3个 | 5个 |
| **真实社交** | ❌ 无 | ❌ 无 | 待定 |
| **AI社交** | ✅ AI虚拟宠物 | ✅ AI虚拟宠物 | ✅ AI虚拟宠物 |
| **事件系统** | ✅ 大型求助事件 | ✅ 中型+大型 | ✅ 全部 |
| **背包系统** | ✅ 查看（只读） | ✅ 查看（只读） | ✅ 查看（只读） |
| **日记系统** | ✅ 基础时间线 | ✅ 完整时间线 | ✅ 完整+统计 |
| **Unity PC端** | ❌ 无 | ✅ 大型事件解决 | ✅ 完整 |
| **心宠状态提醒** | ✅ 基础阈值提醒 | ✅ 趋势分析 | ✅ 完整闭环 |

### 2.3 社交隐私：纯AI虚拟宠物

**规则**:
- ❌ 真实用户心宠不能互相看到
- ❌ 真实用户心宠不能互相交互
- ❌ 真实用户不能访问其他用户的心宠数据
- ✅ 场景中显示的"其他心宠"全部是AI生成
- ✅ AI虚拟宠物有名字、外观、简单行为，但不对应真实用户

### 2.4 用户控制权边界

| 操作 | 小程序端 | Unity PC端 | 说明 |
|------|---------|-----------|------|
| **移动心宠** | ❌ 不可 | ✅ 可控制 | 小程序仅观察位置 |
| **触发活动** | ❌ 不可 | ✅ 可触发 | 小程序仅查看活动 |
| **使用物品** | ❌ 不可 | ❌ 不可 | 心宠AI自主使用 |
| **解决事件** | ✅ 可选择 | ✅ 可沉浸式解决 | 小程序面板选择，Unity 3D交互 |
| **切换场景** | ✅ 可查看 | ✅ 可移动 | 小程序查看地图，Unity 自由移动 |
| **查看日记** | ✅ 可查看 | ✅ 可查看 | 两端都只有读权限 |
| **查看背包** | ✅ 可查看 | ✅ 可查看 | 两端都只有读权限 |

**控制状态仲裁**:
- Unity连接时：AI暂停，Unity获得完全控制权（直接修改心宠位置/活动）
- Unity断开时：保存状态，AI恢复自主运行
- 小程序对心宠状态只读（位置/活动/属性由服务端控制），但可提交事件决策命令
- 事件决策由服务端计算结果后写入状态，非客户端直接修改

```

├─────────────────────────────────────────────┤
│                                             │
│          🏷️ 奇幻森林                          │  ← 场景标签
│                                             │
│              🌳  🏰                          │
│                                             │
│                 🐱                          │  ← 心宠精灵
│                /|\                         │
│                / \                         │
│                                             │
│      🐶      🐰      🦊                     │  ← AI虚拟宠物
│                                             │
├─────────────────────────────────────────────┤
│  🎒 正在上课...    📍 奇幻森林                │  ← 状态浮层
├─────────────────────────────────────────────┤
│  [🗺️地图] [🤝帮助] [🎒背包] [📖日记]         │  ← 4按钮 200rpx
└─────────────────────────────────────────────┘
```

### 3.2 状态栏

**三个状态项**:
- ❤️ **心情**: 0-100，影响心宠表情和动画频率
- ⚡ **能量**: 0-100，决定可执行活动强度
- 👥 **社交**: 0-100，影响与虚拟宠物互动意愿

**进度条样式**:
- 高度: 12rpx
- 圆角: 6rpx
- 渐变: 低值色 → 高值色
- 动画: 宽度变化 600ms ease-out

**低状态警告** (<30%):
- 图标每2秒闪烁
- 数值加粗变色
- 进度条 shake 动画

### 3.3 场景区域

**奇幻森林** (MVP唯一场景):
- 像素风背景图 (750×1334 PNG-8)
- 3层视差效果 (远景0.2x / 中景0.5x / 近景1.0x)
- 心宠精灵: 64×64像素，8 FPS动画
- AI虚拟宠物: 同屏最多5个，48×48像素

**状态浮层**:
- 位置: 场景底部
- 显示: 当前活动 + 场景名称
- 背景: 半透明深色 + 毛玻璃效果

### 3.4 四个功能按钮

| 按钮 | 图标 | 正常状态 | 有事件时 |
|------|------|---------|---------|
| **世界地图** | 🗺️ | 紫色图标 | 不变 |
| **提供帮助** | 🤝 | 灰色，"暂无求助" | 闪烁+红点+事件数量 |
| **心宠背包** | 🎒 | 紫色图标 | 不变 |
| **心情日记** | 📖 | 紫色图标 | 不变 |

**按钮样式**:
- 图标区域: 88rpx × 88rpx，圆角矩形
- 背景: --primary-50
- 边框: 3rpx solid --primary-200
- 按下: scale(0.94)，背景变深

### 3.5 事件系统

**大型事件类型**:
1. **学业危机**: "心宠考试失利，需要你的鼓励"
2. **人际冲突**: "心宠和朋友吵架了，需要你的建议"
3. **情绪低落**: "心宠感到孤独，需要你陪伴"
4. **重大选择**: "心宠面临社团选择，需要你的指导"

**事件流程**:
```
服务端触发事件
  ↓
WebSocket推送 event_trigger
  ↓
小程序帮助按钮闪烁 + 红点
  ↓
用户点击帮助按钮
  ↓
弹出事件面板（描述 + 4个选项）
  ↓
用户选择选项
  ↓
POST /events/:id/resolve
  ↓
服务端计算结果，更新状态
  ↓
推送状态更新 + 记录日记
  ↓
小程序展示结果动画
```

**选项影响**:
- 每个选项影响心情/能量/社交（±5到±20）
- 可能获得物品
- 结果记录在日记中

### 3.6 日记系统

**记录内容**:
- 活动切换: "08:00 起床，精神满满 (+5能量)"
- 事件解决: "14:00 [求助事件] 考试没考好 → 你选择了'安慰鼓励' → ❤️ +15心情"
- 物品获得: "16:00 在森林探险时发现了幸运四叶草"

**展示方式**:
- 按日期分组
- 时间线样式
- 左边框颜色区分类型（日常/事件/物品）

### 3.7 背包系统

**规则**:
- ❌ 用户不可主动获取/使用/交易物品
- ✅ 心宠AI自主获取和使用
- ✅ 用户可查看物品名称、数量、效果、来源

**物品类型**:
- 🍪 食物: 恢复能量
- 🧸 玩具: 提升心情
- 🎁 礼物: 社交道具
- 🏆 收集品: 纯展示

## 5. 虚拟状态风险控制

### 5.1 数据使用边界

❌ **禁止**:
- "根据用户心率数据，心宠心情低落，用户可能抑郁"
- 任何将虚拟属性映射到真实心理疾病的表述

✅ **允许**:
- "心宠已连续3天心情低于30，建议关注"
- 仅针对虚拟宠物的游戏化表达

### 5.2 状态提醒升级流程

```
Level 1 (系统内部)
├── 心宠属性异常（心情<20持续2天）
└── 仅记录日志

Level 2 (用户提醒)
├── 心宠心情<10持续1天
└── 推送微信订阅消息: "你的心宠看起来不太开心"

Level 3 (管理员查看)
├── 心宠连续7天心情<15
└── Sentinel管理后台展示状态提醒（仅虚拟数据）

---

### 5.3 平台安全事件（独立于心宠状态提醒）

**触发源**: 用户主动表达自伤/自杀倾向（非心宠虚拟值推断）

**处理流程**:
```
用户在任意渠道（咨询、问卷、消息）表达自伤倾向
  ↓
平台安全机制触发（与心宠系统无关）
  ↓
立即通知值班咨询师
  ↓
启动危机干预流程
```

**关键区别**:
- 心宠状态提醒：基于虚拟宠物数值，仅作参考
- 平台安全事件：基于用户明确表达，立即响应
```

### 5.3 用户同意与退出

- **首次打开**: 展示免责声明，确认后开启
- **免责声明**: "心宠是虚拟娱乐功能，不代表真实情绪状态"
- **随时退出**: 设置中可关闭心宠功能，数据保留30天后删除

## 6. Unity PC端设计（Phase 2）

### 6.1 定位
**PsyTwin-Unity** 是心宠功能的 PC 端 3D 扩展。当用户的心宠在小程序中触发**大型事件求助**时，系统邀请用户前往线下心理咨询室，通过 PC 端 Unity 游戏以**第一人称沉浸视角**进入心宠的虚拟世界，亲自帮助心宠解决问题。

### 6.2 与小程序的核心差异

| 维度 | 小程序 (Pocket) | PC端 (Unity) |
|------|----------------|--------------|
| **视角** | 2D俯视/侧视 | 3D第一人称/第三人称 |
| **心宠控制** | AI自主，用户不可控 | 用户直接控制心宠 |
| **交互深度** | 轻度（点击按钮） | 深度（WASD移动、物理交互） |
| **触发场景** | 日常使用 | 大型事件求助时线下咨询 |
| **渲染** | Canvas 2D像素风 | Unity 3D (Built-in RP) |
| **网络** | WebSocket实时同步 | HTTP API断点同步 |

### 6.3 控制模式

**第一人称视角**:
- 心宠眼睛高度视角
- WASD移动，鼠标控制视角
- 看不到自己的心宠模型
- 用于沉浸式解决问题

**第三人称视角**:
- 心宠后方上方视角
- 可观察心宠日常生活
- 按 `V` 键切换

**控制权仲裁**:
- Unity连接时：AI暂停，用户获得完全控制权
- Unity断开时：保存状态，AI恢复自主运行
- 小程序在Unity控制期间显示"心宠正在线下咨询中"

### 6.4 3D场景设计

5个3D场景与小程序2D场景一一对应：

| 场景ID | 名称 | Unity 3D表现 |
|--------|------|-------------|
| `fantasy_forest` | 奇幻森林 | 3D魔法森林，有树木、草地、小溪、蘑菇 |
| `counseling_room` | 心理咨询室 | 3D温馨咨询室，有沙发、书架、绿植 |
| `open_forest` | 开放森林 | 3D开阔林地，有长椅、篝火、野餐区 |
| `classroom` | 教室 | 3D教室，有课桌椅、黑板、窗户 |

### 6.5 沉浸式事件解决

**示例："心宠考试失利，心情低落"**

```
Unity 场景：教室
├── 心宠坐在课桌前，头低垂（悲伤动画）
├── 地上有散落的试卷
├── 周围环境昏暗（心情影响光照）
└── 玩家（控制心宠）可以：
    ├── 走近窗户 → 触发选项"看看窗外的风景"
    ├── 点击试卷 → 触发选项"分析错题"
    ├── 走向讲台 → 触发选项"向老师请教"
    └── 坐在椅子上 → 触发选项"深呼吸冷静一下"
```

## 7. MVP验收标准

### 7.1 Must Have
- [ ] 用户首次打开页签，自动生成心宠
- [ ] 心宠在奇幻森林自主移动、活动（AI驱动）
- [ ] Canvas显示心宠精灵动画（8 FPS）
- [ ] 场景中有3-5个AI虚拟宠物在活动
- [ ] 状态栏显示心情/能量/社交（带动画）
- [ ] 大型事件触发后，帮助按钮闪烁+红点
- [ ] 用户解决事件后，状态更新并记录日记
- [ ] 日记面板显示时间线记录
- [ ] 背包面板显示物品（只读）
- [ ] 心情持续低于阈值时，Sentinel管理后台收到状态提醒
- [ ] WebSocket状态同步正常
